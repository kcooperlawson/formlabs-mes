**v3.7.0 - Sunday, Aug 30, 2026 (Device Gateway — Multi-Protocol Machine Integration)**
* **Protocol-Agnostic Device Gateway:** Shipped a new subsystem for wiring real floor hardware — filling/pump controllers, bench scales, and eventually label printers — into the MES without hardcoding any one protocol. Every machine gets one row in a new `devices` table with a protocol column; the actual polling logic for each protocol lives behind a shared `DeviceAdapter` interface (`connect()` / `poll()` / `close()`) in its own adapter file, so the gateway loop, the admin UI, and the write path never need to know which protocol a given device speaks. Adding support for a machine that speaks a protocol nothing here covers yet is one new adapter file plus one line in `device_gateway/registry.py` — nothing else changes.
* **Six Adapters Shipped Out of the Box:** `modbus_tcp` (PLC/HMI panels with a Modbus TCP server — the likely fit for the filling/pump controllers), `modbus_rtu` (the same over RS-485/RS-232 serial for panels with no Ethernet port), `opcua` (newer Industry 4.0 equipment), `mqtt` (IIoT-style machines or a bridge device publishing to a broker), `serial_ascii` (bench scales streaming plain text over RS-232/USB — the likely fit for the ULINE/Mettler Toledo cart scales, matched per-tag against a configurable regex rather than a hardcoded vendor format), and `http_poll` (controllers/printers exposing a local status JSON endpoint).
* **Zero-Duplication Write Path:** The gateway never writes `ProductionLog` rows with raw SQL — `device_gateway/writer.py` calls straight into `crud.py`'s existing `add_hourly_log()`, the exact function `Operator_Form.py` calls for a hand-typed count, tagged with operator name "Automated Gateway". Every business rule already in `crud.py` (`AssignedRun` progress toward target, marking a run "Done", FK resolution against users/pump_stations/resin_specs) applies to machine-sourced data automatically, and `Analytics_Hub.py`, `Manager_Cockpit.py`, `Live_Reactors.py`, and `Tv_Dashboard.py` needed zero changes — they already read `ProductionLog`/`AssignedRun` and have no way to tell a keyboard entry from a machine one. `ReadingWriter` also resolves the correct shift bucket from `PlantSettings`' configured start times and converts a machine's lifetime cycle counter into a per-poll delta (`units_poured_total` → previous-vs-current) for devices that don't report a ready-made per-cycle count.
* **Raw Telemetry Audit Trail:** Every normalized reading — regardless of whether it triggers a production-log write — is also persisted to a new append-only `device_readings` table (fault codes, machine state, raw weight curves, uptime), giving Analytics a dedicated place to query machine-level telemetry directly later without touching `ProductionLog`.
* **Tag Mapping & Canonical Metrics:** Added `device_gateway/normalize.py`'s shared vocabulary (`weight_g`, `net_weight_g`, `units_poured_delta` / `_total`, `cycle_complete`, `machine_state`, `fault_code`, `resin_lot_number`, `scrap_count`, `labels_printed_delta` / `_total`, `print_fault`, `level_pct`, `temperature_c`) so every adapter, whatever protocol it speaks, normalizes into the same set of names — `writer.py` only ever has to understand this list, not one raw-tag naming scheme per vendor. A new `device_tag_maps` table stores the per-device mapping from a raw tag (register address, node id, MQTT topic, regex group, or JSON path, depending on protocol) to one of these canonical metrics, along with data type, scale factor, and unit.
* **Background Poller Service (`run_gateway.py`):** New standalone long-lived process — deliberately separate from `streamlit run Home.py`, since Streamlit's rerun-on-interaction model isn't a fit for continuous polling. `device_gateway/service.py` runs one thread per enabled device at that device's own `poll_interval_s`, rescanning the devices table every 10 seconds so a device added or enabled on the admin page starts polling within seconds with no restart. A device whose adapter throws (unreachable host, wrong COM port, bad credentials) doesn't take the rest of the gateway down — that device's worker logs the error, flips its status to Error with `last_error` set, and retries with exponential backoff up to 60 seconds. Intended to run on a floor PC with actual network/USB/COM-port access to the equipment, not necessarily wherever Postgres lives; documented for wrapping as a Windows service (nssm/Task Scheduler) or a systemd unit with `Restart=on-failure`.
* **Device Registry Admin Page:** New `pages/Device_Registry.py`, admin-gated like the rest of the IT console. A Devices tab lists every registered machine with live status (Online/Offline/Error/Unknown), last-seen time, and an inline tag-map editor per device; an Add/Test Device tab renders protocol-specific connection fields (host/port/unit id for Modbus TCP, COM port/baud/parity for Modbus RTU, endpoint/credentials for OPC-UA, broker host/port/credentials for MQTT, COM port/baud/request command for serial ASCII, URL/method for HTTP) and a Test Connection probe that connects ad hoc and shows the raw response before anything is saved; a Recent Readings tab charts and tables a device's `device_readings` history over a configurable lookback window. Added the "Device Gateway" 🔌 link to the IT Admin sidebar.
* **Schema — devices / device_tag_maps / device_readings:** New `device_models.py` (`Device`, `DeviceTagMap`, `DeviceReading`) and `device_crud.py` (same `ScopedSession`-per-call pattern as `crud.py`), wired into the `database.py` facade with two import lines so every existing page's `from database import ...` style keeps working unchanged. Shipped as Alembic migration `0002_device_gateway_schema` (chained onto `0001_baseline`) — purely additive, no existing table touched, with `pump_station_id`/`reactor_id` foreign keys (`ON DELETE SET NULL`) tying a device to the same `PumpStation`/`Reactor` rows `ProductionLog` and `AssignedRun` already key off of. Runs automatically on next boot through the existing `init_db()` → `alembic upgrade head` path introduced in v3.6.0 — no manual migration step needed.
* **Deployment Docs:** Added `README_DEVICE_GATEWAY.md` (architecture rationale, wiring steps, and a suggested rollout order starting with a bench scale over `serial_ascii` before tackling the filling/pump HMI) and `requirements-device-gateway.txt` (`pymodbus`, `pyserial`, `opcua`, `paho-mqtt`) for the new process's extra dependencies.

**v3.6.1 - Saturday, Aug 29, 2026 (Avatars Actually Rendering)**
* **Sidebar Avatar Fix:** `avatar_filename` was being saved to the database on every "Save Avatar" upload, but nothing ever read it back — `authenticate_user()`, `get_user_by_session_token()`, and `check_authentication()` never included it in the session data, and every sidebar header rendered a hardcoded 👤 emoji instead of the uploaded picture. The sidebar (all 16 pages) now shows the user's actual avatar next to their name when one is on file, falling back to the emoji otherwise. Added `get_avatar_path()`/`get_avatar_data_uri()` (`utils.py`) as the single place that resolves a stored filename to a real file, so a deleted/missing avatar file degrades to the fallback instead of erroring. The Account & Preferences popover now also previews the current avatar, and the IT Admin console's own popover — which never had an avatar uploader at all — gained one for parity with every other role.
* **Floor Comms Chat Avatars:** `Mgr_Floor_Comms.py` and `Operator_Form.py`'s manager↔operator chat threads used a fixed 👨‍💼/👷 icon per role regardless of who actually sent the message. `get_chat_history_df()` now outer-joins on `FloorMessage.sender_id` to pull the real sender's current avatar, so each chat bubble shows that person's own picture (falling back to the role emoji for senders with no avatar or pre-FK-backfill messages).
* **Feedback Inbox Avatars:** The IT Admin "Floor Feedback & Issue Inbox" now shows the submitter's avatar next to their name on each card. `Suggestion` has no FK to `users` (free-text submitter name only), so `get_all_suggestions_df()` matches best-effort by current display name — same fallback approach already used elsewhere for legacy string-only lookups — and simply shows no avatar for a name that no longer matches an account.

**v3.6.0 - Saturday, Aug 29, 2026 (Migration Framework, Operator Consolidation & Observability)**
* **Alembic Migration Framework:** Replaced the hand-maintained, 30+ line list of raw `ALTER TABLE` strings in `init_db()` — previously wrapped in a silent try/except that couldn't distinguish "column already exists" from a real failure — with a proper versioned Alembic migration history (`migrations/`, `alembic.ini`). `init_db()` now auto-detects and handles the one-time transition: a brand-new database runs the full baseline migration from scratch, while an existing production database is automatically stamped at baseline rather than re-running `CREATE TABLE` against tables that already exist. Future schema changes are now `alembic revision --autogenerate` instead of another appended string.
* **Historical Analytics Operator Filter Fix:** `Mgr_Historical.py`'s Operator Filter and its "Total Output by Operator" chart previously disagreed after a mid-history rename — the chart consolidated by resolved identity while the filter still matched on the raw logged string. `get_production_logs_df` gained an `operator_id`-based filter path; selecting a known operator now pulls their full history regardless of what name was logged at the time, with the exact-string match retained as a fallback for legacy/deleted-account names.
* **Backup/Restore Target Fix:** `create_database_backup`/`restore_database_backup` were hardcoded to `localhost` / `postgres` / `formlabs_mes` and a Windows-only `pg_dump.exe` path, silently ignoring `DB_URL` entirely — meaning backups could target the wrong database the moment the app was pointed anywhere else. Now derives host/port/user/dbname/password directly from `DB_URL` via SQLAlchemy's `make_url`, and resolves `pg_dump`/`psql` via an optional `PG_BIN_DIR` env var (Windows) or `PATH` (Linux/Mac/containers). Also removed a duplicate, stale copy of both functions that had been silently shadowing the real ones through the `database.py` facade.
* **Centralized Logging (`app_logger.py`):** Added a shared logger (console + rotating file under `logs/`) and wired it into every previously-silent exception handler — `backfill_foreign_keys()`, `add_resin_spec()`, `add_suggestion()`, `add_reactor()`, and critically the backup/restore functions, which now log `pg_dump`/`psql`'s actual stderr on failure instead of failing with zero diagnostic trail.
* **Alembic Config Encoding Fix:** Fixed a `configparser` interpolation crash in `migrations/env.py` when `DB_URL` contains a URL-encoded character (e.g. `%21` for `!` in a password) — literal `%` is now escaped as `%%` before being handed to Alembic's config object.
* **Account Lockout & Brute-Force Protection:** Hardened `authenticate_user` to track failed PIN attempts per account, automatically locking an account for 15 minutes after 5 consecutive failures. Unknown usernames now return the same generic "Invalid credentials" message as a wrong PIN, closing the username-enumeration gap. Successful logins and admin PIN resets both auto-clear the lockout counter.
* **IT Admin Unlock Console:** The Staff Database table in the Admin Panel now surfaces a live 🔒/✅ status column and a locked-account count. Added a dedicated "Unlock Account" control so IT can clear a lockout instantly without resetting the operator's PIN.
* **Referential Integrity Foundation:** Introduced proper nullable foreign-key columns (`operator_id`, `pump_station_id`, `resin_spec_id`, `sender_id`, `current_resin_id`, `assigned_pump_id`) across `ProductionLog`, `DowntimeLog`, `AssignedRun`, `DailyChecklist`, `CleanlinessAudit`, `FloorMessage`, and `Reactor`, referencing `users`, `pump_stations`, and `resin_specs` with `ON DELETE SET NULL` semantics — deleting a user, pump, or resin no longer risks an `IntegrityError` against historical logs.
* **Self-Healing FK Backfill Engine:** Added `backfill_foreign_keys()`, a safe-to-rerun pass that resolves the legacy free-text name columns (`operator_name`, `pump_station`, `resin_type`, etc.) against their real rows and populates the new FK columns on existing data, wired into the boot sequence and guarded with `st.cache_resource` so it runs once per server process.
* **Write-Path FK Resolution:** Every log-creation and reconciliation function (`add_hourly_log`, `add_downtime_log`, `add_cleanliness_audit`, `create_assigned_run`, `complete_run_with_custom_total`, `submit_daily_checklist`, `send_floor_message`, and all three reactor reconciliation routines) now resolves and stores the matching FK alongside the legacy string at write time, going forward.
* **Operator Identity Consolidation:** The Analytics Hub's Operator Contribution Matrix and the TV Dashboard's Top Pourers leaderboard now group by the resolved `operator_id` mapped to each operator's *current* display name, so a mid-history rename no longer fragments one person's output across two rows.
* **Bcrypt Cryptographic Migration:** Completely stripped legacy raw SHA-256 hashing and implemented industry-standard `bcrypt` across the entire application. Integrated automated salting mechanisms into user creation, password updates, and authentication pipelines to defend against dictionary attacks.
* **Database Monolith Decoupling:** Successfully dismantled the 1,000+ line `database.py` monolith into a highly modular, four-pillar architecture:
    * **`db_core.py`:** Isolated SQLAlchemy engine, session definitions, and database URL bindings.
    * **`models.py`:** Extracted all declarative base classes and table schemas into a dedicated object layer.
    * **`crud.py`:** Centralized all Create, Read, Update, and Delete operations and SQL querying logic.
    * **`utils.py`:** Segregated operating system interactions, directory generation, and database backup routines.
* **Facade Pattern Routing Hub:** Engineered the legacy `database.py` file into a lightweight import routing hub. This completely shielded the front-end `pages/` directory from the structural refactor, ensuring zero broken imports across the UI.
* **Zero-Latency UI (Thread-Blocking Elimination):** Conducted a global codebase sweep to eliminate all synchronous `time.sleep()` calls that were actively freezing the server thread for concurrent users.
* **Optimized Session Loops:** Rewrote the "Double-Take" auto-login loop, explicit logout sequence, and theme selection functions to utilize instant `st.rerun()` triggers, drastically speeding up module-to-module navigation.
* **Asynchronous UX Notifications:** Replaced blocking form-submission success messages with asynchronous `st.toast()` notifications, allowing the application to reload instantly while gracefully persisting success messages across the rerun state.
* **Execution Order Optimization:** Repaired critical application boot sequences by hoisting baseline catalog constants above seed functions and relocating database initialization calls (`init_db`) to the absolute end of the application load cycle.
* **Emergency Admin Utility:** Engineered a standalone `create_admin.py` terminal script equipped with `.env` injection. This provides a permanent developer backdoor to force-provision securely hashed superuser accounts in the event of a system lockout or a total database wipe.
